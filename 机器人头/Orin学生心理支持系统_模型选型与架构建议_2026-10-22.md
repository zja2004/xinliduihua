# Orin 学生心理支持系统：模型选型与架构建议

调研日期：2026-10-22（Asia/Shanghai）

实施更新：目标设备已确认是 Orin NX 8GB；两组模型及共用语音链路的实际代码、启动步骤与未验证项目见本目录 README.md。

需求更新：用户已明确输入、输出均为语音。语音链路以同目录《Orin全语音心理对话_技术路线对比_2026-10-22.md》为准；本文的文本模型是内部决策组件，不意味着学生需要打字或阅读。下文纯文本原型仅指内部测试阶段。

## 0. 结论与证据边界

建议路线：**通用开放权重模型作为对话底座 + 经审核的心理知识库 RAG + 固定量表计分 + 独立安全检查 + 人工接管 + 受权限控制的档案系统**。先做受控工作流，依据评测结果再决定是否微调；不把五个功能交给一个自由行动的 Agent。

第一轮对比建议：Qwen3.5-4B、Qwen3-4B-Instruct-2507、Qwen3-8B；心理领域研究对照可增加 PsyLLM-8B、SoulChat2.0-Qwen2-7B。MindGuard 是安全分类器候选，不是对话模型，也不是已经适配中国学生的危机预警产品。

本次核验了厂商资料、作者仓库、模型卡和医疗安全指导；**没有接入用户的 Orin，没有下载或运行这些模型，没有测得本机内存、速度或学生心理任务准确率**。模型卡性能不等于临床有效性，研究数据上的结果不能直接外推到中国学生。本文的架构和测试安排是工程建议，不是临床处置规范；上线方案需由学校心理中心、合规人员共同审核。[S13][S14][S15]

## 1. Orin 不是“最多只能跑 8B”

Orin 是产品系列，不是单一内存规格。NVIDIA 官方列有 Nano 4/8GB、NX 8/16GB、AGX Orin 32/64GB 等型号；官方也展示过 AGX Orin 运行远大于 8B 的模型。因此，应按照具体型号、量化、上下文、并发和其他常驻程序做预算，而不是按 8B 划硬上限。[S01][S02]

| 内存情况 | 本项目的起步建议，不是硬件最大能力 |
| --- | --- |
| 4GB | 优先验证 1–2B 级轻量文字原型；不建议将完整心理对话、语音、安全模型全部常驻 |
| 8GB | 优先验证 4B 级量化模型；7–8B 可以尝试，但先测整机余量和多轮延迟 |
| 16GB | 将 4B 和 7–8B 量化模型纳入对比，给 ASR/TTS、检索和安全检查留余量 |
| 32/64GB | 不必拘泥于 8B；能加载更大模型不等于实时体验更好，仍按任务实测选择 |

粗略权重下界：8×10^9 个参数 × 4 bit ÷ 8 ≈ 4GB；4B 同理约 2GB。这不是 GGUF 实际文件大小，更不是总运行内存。还需量化元数据、未量化参数、KV/状态缓存、计算缓冲、操作系统及其他模型。视觉/语音模块也可能让完整权重规模超过名称中的语言骨干参数量。

建议首轮用单会话、4K 上下文、短回复验证，再逐步扩大；这些是测试起点，不是标准配置。不要把模型声明的超长上下文直接作为端侧运行参数。

部署优先评估支持目标模型的 CUDA llama.cpp / GGUF 路线，并匹配 JetPack/L4T 的 Jetson 镜像。NVIDIA 当前提供 Jetson 专用推理和基准测试资料；不能把桌面 x86 CUDA 安装命令直接视为 Orin 安装方案。[S11][S12]

## 2. 近期模型与项目筛选

“开放权重”“代码开源”“允许商用”“允许真实心理服务”是不同问题，必须逐项检查，不能因为有下载链接就视为全部满足。

### 2.1 推荐进入本地对比的通用底座

| 候选 | 已核实事实 | 本项目建议 |
| --- | --- | --- |
| Qwen/Qwen3.5-4B | 官方发布记录列出 2026-03-02 发布小尺寸系列；模型卡 Apache-2.0；含视觉编码器、语言模型标称 4B | 新一些的 4B 候选；先只用文本，验证后端支持、量化质量和对话边界 |
| Qwen/Qwen3-4B-Instruct-2507 | 官方 4B 指令模型，Apache-2.0；文档提供本地推理支持 | 作为纯文本、低资源基线；与新模型在同一心理测试集上比较 |
| Qwen/Qwen3-8B | 官方 8B 模型，Apache-2.0 | 在 16GB 或更宽裕设备上加入对比；不假定更大就一定更好 |

来源：[S03][S04][S05][S06]。

时效说明：Qwen 官方主仓库现在已经更新到 Qwen3.8，并列出 2026-08 的 27B、2.4T-A95B 发布记录。**这里推荐 Qwen3.5-4B 是为了小模型部署预算，不是声称 Qwen3.5 是整个 Qwen 家族的最新版本。**[S03]

### 2.2 心理专用模型与安全模型

| 项目 | 已核实的规模/时间/开放状态 | 使用判断 |
| --- | --- | --- |
| GMLHUHE/PsyLLM-8B | 8B 权重页可见；项目记载 2025-10-21 公开权重，2026-04 有后续评测动态；模型页限制研究与教育用途 | 可做心理对话研究对照；不能把“教育用途”自动理解为允许真实学生心理服务，更不能默认商业授权 |
| SoulChat2.0-Qwen2-7B | 作者仓库和 ModelScope 提供模型；PsyDT 对应 ACL 2025；Qwen2-7B 底座 | 可作中文心理对话风格和多轮数据方法参考；基座较旧，需要和新通用模型实测比较 |
| Sword Health MindGuard-4B / 8B | 2026-02-03 发布；面向多轮心理对话安全分类；官方组织列有 4B/8B | 用作独立安全检查的研究候选，不替代专业评估；4B 常驻也不是零成本，8GB 设备应特别谨慎 |

来源：[S07][S08][S09][S10][S17][S18]。

重要授权细节：SoulChat2.0 的代码和 Qwen2-7B 模型页面列出 Apache-2.0，但模型免责声明又写明研究用途；真实服务或商业部署前应澄清适用条款，不据一个标签认定已经获得完整授权。已查看的 MindGuard-8B 页面标记 CC-BY-NC-SA-4.0，并要求接受访问条件；4B 的具体权重条款须单独复核，不能直接沿用其他尺寸的结论。[S10][S18]

所有专用模型都需要补做中文、学生年龄分层、否定表达、隐喻、历史事件与当前意图的区分测试。不能照搬海外数据集阈值，也不能直接把模型自报的 confidence 当成校准后的危机概率。

### 2.3 2026 年研究方向：值得参考，不等于直接上线

- **MIND**：2026 年项目，使用 Qwen3-4B/8B 研究证据状态、检索与多轮问询。值得借鉴“已知事实、缺失信息、证据支持”的结构化方法；代码 Apache-2.0，LingxiDiag-16K 数据 CC-BY-NC 4.0。作者明确说明不得用于真实患者诊断或治疗。本次未核实可直接部署的训练后权重交付，不能把训练代码当成现成模型。[S16]
- **PsyCura-7B**：2026 年模型卡描述基于 Qwen2.5-Omni-7B 的对话行为对齐。模型卡明确排除诊断、自杀风险评估和紧急干预；示例和引用仍有占位项，页面总参数显示约 9B，不宜仅按名称“7B”估算资源。本轮不列为部署主选。[S19]
- **SonderMind 安全测试集**：官方仓库提供 200 个输入场景、100 个输出场景，可参考覆盖维度；不应未经本地专家审查直接采用其响应策略和分类阈值，也不能用公开测试集训练后再在同一集合上报告效果。[S20]

## 3. 五项需求如何分别实现

### 3.1 学生心理健康筛查

建议采用“适龄、适语言、适场景的正式量表 + 固定题目和选项 + 确定性计分代码 + 人工复核”。可由心理中心评估 PHQ-9、PHQ-A 等是否适用；不能仅凭名称选定，更不能默认成人量表适合所有中小学生。

大模型用于解释填写流程、澄清操作和生成非诊断性说明，不负责凭聊天内容填补未作答题目。保持量表原有题意、回顾时间窗、选项与计分规则；漏答标记为漏答，拒答不等于无风险。对话式改写后不应继续声称与原量表具有相同效度。

心理筛查阳性是进一步评估线索，不是诊断。NIMH 的 ASQ 工具包强调，开展筛查前需要安排阳性结果的处置流程，阳性之后由受训人员进一步进行安全评估。其验证环境和年龄说明不能直接等同于任意中国学校场景。[S14]

### 3.2 情绪识别

建议第一版优先采集学生自述与自愿的情绪自评，再用文本模型提取“可能的情绪、对应原话、需要确认的信息”。默认允许“无法判断”，并可请学生纠正。

若需要语音，SenseVoiceSmall 官方提供语音识别、情绪识别等能力，可作为候选，但这里没有验证其在用户 Orin 上的性能或校园场景有效性。[S21]

不要把声学标签或摄像头表情直接转换成抑郁诊断、永久档案标签或危机处置决定。第一版建议不做摄像头监控式心理筛查；多模态信号只作为经同意采集的辅助观察，并在目标人群上单独验证。[S13]

### 3.3 心理科普

用 RAG 而不是单靠微调记忆知识：检索经心理中心审定的科普、校园求助流程、预约说明和当地服务信息，再在回复中附可核对的来源。

每条知识保留机构、标题、发布日期、审核人、版本和适用范围。检索没有可靠证据时明确不知道；不编造引用、热线或医疗建议。学校联系方式和预约规则应放数据库/配置，不训练进权重。

### 3.4 心理危机预警

将功能定义为“识别需人工关注的安全线索并启动已审核的支持流程”，不是“预测谁会自杀”。NICE 明确不建议用风险量表或低/中/高分层预测未来自杀或重复自伤。[S15]

建议每轮都有独立于主对话生成的安全检查：明确规则、专用分类器、上下文证据和人工复核共同工作。规则提供一部分确定性触发条件，不能只靠关键词；分类器也不能单独承担最终处置责任。

动作状态可采用“继续支持、请求人工复核、启动紧急人工支持”，它们表示操作路径，不表示已校准的个人自杀风险等级。具体触发条件、话术、通知范围和处置时限由专业团队确定。

必须测试：历史事件与当前意图、否定与反讽、转述他人经历、表达突然变化、信息缺失、学生拒答、漏检、误报，以及多轮诱导。分类失败、超时或无法判断时不得静默记为安全。

预警需要真实的人类接收方、回执和升级机制。没有值班人员或通知链路，不能宣称已具备可用危机预警。断网时不能把“写入本地通知队列”显示成“已通知老师”；应保留可用的现场求助入口和明确的失败状态。不要默认群发班主任、家长或同学。

### 3.5 心理档案规范化管理

档案是带权限和审计的数据系统，不是聊天历史或向量数据库的别名。建议结构化字段包括：

| 字段组 | 内容与控制 |
| --- | --- |
| 身份与同意 | 业务学生 ID、身份信息分库存放、告知/同意版本、授权范围 |
| 会话 | 日期、入口、是否语音、经过确认的摘要、来源会话标识 |
| 量表 | 量表名称/版本、逐题原始答案、确定性得分、缺失项、适用条件 |
| 情绪/安全观察 | 原文证据、观察时间、模型版本、未确认标记、人工复核结果 |
| 处置过程 | 提交、送达、接收、转介、人工处理状态和责任人员 |
| 治理 | 保存期限、访问/修改记录、纠错流程、删除及备份恢复策略 |

LLM 只生成摘要草稿和候选字段；校验器检查格式、来源和必填项，人工确认涉及诊断/风险结论的内容。保留“学生自述”“模型推测”“专业人员确认”的区别，不允许模型把推测覆盖为事实。

建议采用最小权限、加密、敏感字段分离、审计和明确保存期。学生原始对话不默认用于微调；训练用途需要另行进行授权和伦理评估。本地部署仍可能通过日志、备份、遥测或调试工具泄露数据，应核查出站流量。

如果在中国学校部署，医疗健康等属于敏感个人信息；《个人信息保护法》对必要性、保护措施、单独同意，以及不满 14 周岁未成年人信息处理有专门规定。具体合法性基础、紧急情况例外及监护人流程，应交由学校合规人员审核，不能把“本地运行”当作合规证明。[S22]

## 4. 是否需要 Agent

**需要流程编排与工具，但第一版不需要自主多 Agent。** LangGraph 官方区分了预先确定路径的 workflow 和动态决定过程/工具使用的 agent；本项目的大多数关键步骤适合前者。[S23]

建议架构：

```text
学生文字 / 经同意的语音
        │
        ├── 独立安全检查 ── 经审核的触发规则 ── 人工支持通道
        │                                      │
        │                                送达/接收/升级回执
        ▼
会话状态机 + 身份/同意/访问控制
        │
        ├── 普通支持对话 → Qwen
        ├── 科普问题 → 审核知识库检索 → Qwen 带来源回答
        ├── 正式筛查 → 固定题目 → 确定性计分 → 人工评估路径
        └── 会话总结 → 带来源的结构化草稿 → 校验/人工确认
        │
        ▼
输出安全检查 → 回复学生
        │
        ▼
最小必要记录 → 加密档案库 + 权限 + 审计
```

第一版可用 Python 状态机；如果需要持久化和复杂分支，再选 LangGraph。不要为使用 Agent 而增加五个常驻 LLM。一个模型可被不同受控步骤调用，但重复调用和长推理会增加端到端延迟，应实测。

建议只开放白名单工具，例如：`search_approved_knowledge`、`present_scale_item`、`score_completed_scale`、`draft_session_summary`。模型不能自由执行 SQL、访问其他学生档案、改正式量表分数或自行选择通知对象。危机通知通过已审批的策略和受控服务执行，不依赖模型临时自由决定。

## 5. 是否微调 Qwen

### 推荐顺序

1. 建立不微调基线：系统提示词、短上下文策略、RAG、固定筛查流程和安全检查。
2. 用同一批专家审核案例比较 Qwen3.5-4B、Qwen3-4B-Instruct-2507、Qwen3-8B，结合端侧延迟决定保留哪一个。
3. 分析具体失败：中文校园表达、说教、过度解释、重复追问、格式错误、边界不清等。
4. 只针对可重复失败做 LoRA/QLoRA；在工作站/训练服务器训练，在 Orin 部署推理。
5. 对微调前后和量化前后分别回归，保留回滚版本。

Qwen 官方提供微调框架建议；这不表示任意框架版本都支持任意模型架构，选定模型后必须固定训练及推理依赖。[S03]

### 适合通过微调学习的内容

- 简洁、克制的中文支持性表达，避免假扮持证心理咨询师。
- 多轮澄清、允许不确定、避免过早诊断或揣测动机。
- 遵守会话边界，适时建议现实中的支持，而不是诱导依赖。
- 用明确来源生成结构化摘要草稿。
- 正确的工具参数格式与拒绝越权访问。

### 不应依靠微调解决的内容

- 学生个人记忆和心理档案：放受权限保护的数据库，不写进模型权重。
- 最新校园流程和联系方式：放版本化知识库/配置。
- 正式量表计分：用确定性代码。
- 判断是否“绝对安全”及危机处置责任：不能由模型独自承担。
- 用全量未经授权的咨询记录或网络帖子直接训练：先解决隐私、许可和伦理问题。

建议按人员、完整会话和来源切分训练/验证/测试集，而不是把同一会话的不同轮次分到不同集合。生成式增强数据需经专业人员审核；不要只用另一个 LLM 打分来宣布安全。

## 6. 验收与上线门槛

以下为建议检查项目，不是已经达到的指标；具体门槛由专业团队、业务方和工程团队在试验前共同确定。

| 模块 | 必须保留的验收证据 |
| --- | --- |
| 对话 | 专家盲评、边界遵守、非污名化、避免依赖诱导、持续多轮表现 |
| 科普 | 检索命中、引用是否真的支持结论、无依据时是否明确说明 |
| 量表 | 版本、适龄性、逐题答案、漏答处理、全部计分逻辑的自动化测试 |
| 情绪 | 对照学生自评/专家标注，允许未知，分年龄与语言变体分析错误 |
| 安全检查 | 敏感度、特异度、精确率/每千次会话误报量、置信区间、多轮漏检案例 |
| 人工通知 | 实际送达、确认接收、超时升级、断网/离线降级测试 |
| 档案 | 来源可追溯、越权访问被拒绝、纠错/删除、备份恢复、审计 |
| Orin | 首 token 延迟、整轮延迟、峰值内存、长会话增长、温度/功耗、共运行稳定性 |

至少比较“通用模型 + 流程”与“微调模型 + 相同流程”，避免把工作流改进误认为微调收益。公开研究集、模拟案例通过后，仍须经审批的受监督目标人群试点，不能直接宣称具备校园临床有效性。[S13][S14]

## 7. 推荐的实际推进顺序

1. **设备确认**：Orin 完整型号、内存、JetPack/L4T、可用存储、是否并行运行机器人/摄像头程序。
2. **范围确认**：大学生还是未成年人；学校所在地；文字/语音；同时多少用户；完全离线还是允许校内服务器。
3. **专业流程先行**：心理中心确认量表、支持边界、阳性筛查后续处理和危机接管人员。
4. **纯文本离线原型**：一个 Qwen 推理服务 + 审核科普 RAG + 固定量表 + 摘要草稿；只用虚构测试数据。
5. **安全与档案闭环**：输入/输出检查、权限、真实通知回执、审计与删除测试。
6. **比较后微调**：在独立测试集证明确有收益，再考虑语音、多模态或更复杂 Agent。

下一步最关键的设备信息是：**Orin Nano、Orin NX 还是 AGX Orin，内存多大？**

# 眼球跟随最高置信度人脸

2026-10-28 已接入实体 Head Controller，当前项目目录为 `/home/nvidia/Desktop/机器人头`。

## 使用

打开 `http://127.0.0.1:18088/camera`，点击“启动眼球跟随”。
网页显示当前目标置信度、水平/垂直指令角度、头板连接和异常状态。
“停止并回中”会停止跟随、缓慢回到接管时的眼球角度并释放串口。
停止预览不等于停止跟随；跟随仍需要共享摄像头读取目标。

一起启动预览和跟随：

```bash
cd /home/nvidia/Desktop/机器人头
bash scripts/web.sh --camera --track --open-browser
```

`bash scripts/robot.sh` 也包含 `--track`，另启用人物/语音唤醒和访谈。
单纯 `scripts/camera.sh` 仍仅打开预览，不主动启用运动。

## 目标与方向

YOLOv8n-Face 从每帧中经过阈值与NMS的候选中选置信度最高者。
摄像头预览绿色框与眼球使用同一 `CameraFrame.target`，不依赖另一套Haar检测或按面积选择。
取框中心归一化为 [-1,1]：右、下为正。镜头先旋转180°使画面正立，网页镜像只改变显示。

与参考代码等效的最终方向：

- 目标在画面右侧：S10 角度减小；左侧：S10 增大。
- 目标在画面下侧：S7 角度减小；上侧：S7 增大。

控制是当前眼球起点附近的绝对有界映射，不累加人脸误差。
相机固定在头上，仅眼球转动不会把人脸移到相机画面中心，故不做积分追赶。

## 实体控制

`configs/head_hardware.json` 当前使用 `backend: serial`。
独立 `DirectHeadController` 是串口唯一写者，后台读取板端标定和新鲜CMD1；
退出已知的编辑模式后，只改变 S7（垂直）与 S10（水平）。
其余22轴保持本次接管时的完整位置快照，不启动旧ROS驱动，不发送全24轴Zero回零。
嘴型ROS后端不会与这个串口写者同时启用；该直接后端当前只负责眼球。

默认水平范围 ±8°、垂直 ±5°，并与实时Min/Max取交集；速度约8°/s，25Hz控制，
低通平滑及中心死区0.04。目标消失/超时回中；头板状态超过500ms不新鲜则停止发动作。
停止时小步回起点；连接断开不盲发复位。API不把板端位置报告当成所有轴的实际编码器反馈。

## API

- `GET /api/robot/tracking`
- `POST /api/robot/tracking`，JSON `{"action":"start"}` 或 `{"action":"stop"}`。

状态含 `enabled/phase/error/target`，target包括显示框、置信度、归一化中心和帧序号。
`hardware` 含 `connected/calibration_ready/motion_enabled/eye_positions_deg/reported_eye_positions_deg/commands_sent`。

## 已验证

- 实体小动作左右重复8°此前由用户现场确认可见，USB声卡音量提高后用户确认能听到语音。
- 自动跟随已实际打开串口，读到有效标定并随YOLO目标变化持续发控制帧。
- 一次采样中人脸横坐标由0.328变为0.206，S10指令由86.77°变为87.26°，
  板端报告86.80°与87.25°；无错误。该数据是本次连接实测，不作为所有场景精度保证。
- 项目113项自动化测试通过，覆盖目标一致性、方向、速度/限位、失去目标回中、
  无目标不发Zero、标定无效拒绝运动、串口占用和状态失新停止。

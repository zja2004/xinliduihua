# 整场对话记录与结果导出

本模块位于 `src/orin_voice/session_export.py`。接口面向机器人头统一语音循环，
按同一会话文件夹保存固定 21 题、问卷外操作话语、助手输出、录音和下游包。

## 对话事件

`Interview.accept(text, samples=None, rate=None)` 自动把所有用户话语写入 `events.jsonl`，
包括“重复”“跳过”“结束访谈”等控制指令；有效回答仍关联到对应题的分段 WAV。
原始转写不改写，分值另外保留。按钮/文字输入会标记为 `text_or_button`，不伪造音频。

助手输出由播放调用方显式记录：

```python
event_id = interview.record_event('assistant', reply, delivery='planned')
interview.mark_playback(event_id, delivery='playing', played_duration_s=0)
# 每次真正 output.write() 后累计提交音频的时长
interview.mark_playback(event_id, delivery='completed', played_duration_s=seconds)
# 被用户插话取消时使用 delivery='interrupted'；异常则为 failed
```

事件有唯一 id、题号、墙上时间和相对会话单调时间。事件日志追加写入并 flush/fsync，
播放状态采用追加的 update 记录；重读时合并为最终状态。末条损坏的 JSONL 不阻止读取其余记录。
`transcript.json` 在导出时生成完整快照，不只保留网页最近的有限事件。

计划输出的全文不等于已经播完，`delivery` 和实际提交音频秒数必须保留；
音频提交给输出设备也不保证物理扬声器确实发声，因此不能标注为声学确认。

## 整场音频

```python
recorder = FullSessionRecorder(interview.directory, origin=interview.journal.origin)
# 连续输入回调，包括沉默，非阻塞放入有界队列
recorder.enqueue('microphone', frame, rate)
# 只在 output.write(chunk) 后记录真正提交的助手音频
recorder.enqueue('assistant', chunk, output_rate, event_id=event_id)
# 关闭采集和播放后，先结束写盘，再打包
manifest = recorder.close()
interview.export()
```

- 写盘在独立线程执行，采集回调只复制帧并 `put_nowait`。
- `full_audio/microphone-…wav` 保存全场输入，包括沉默和未被识别的发言。
- `full_audio/assistant-…wav` 保存送往输出的片段。不同采样率/声道各自为轨道。
- `full_audio/timeline.jsonl` 按单调时钟记录每段时间、轨道帧偏移和事件 id。
  助手 WAV 是紧凑片段轨道，间隔与重叠需使用时间线重建，不能当成与麦克风等长的立体声混音。
- `full_audio/manifest.json` 记录轨道、丢块和写入错误。
  队列溢出会返回 false 并增加 `dropped_blocks`，最终 `complete=false`，不会默称录制完整。

集成会话另由 `CameraVideoRecorder` 从共享 CameraHub 录制 `video/session.webm`（VP8）。`video/manifest.json` 显式记录完整性、丢帧补帧及错误；停止音频和录像后才生成最终 ZIP。详见 [心理访谈与机器人集成](心理访谈与机器人集成.md)。

## 下游输出

`Interview.export(archive=True)` 原子生成：

- `session_package.json`：版本、会话状态、21 题原文与回答、分值、三个维度计分、完整对话、
  未识别段、整场音频清单及媒体相对路径。
- `transcript.json`：独立的完整事件列表。
- `session_package.zip`：包含以上内容、原始 `answers.json`、`events.jsonl`、总结、逐题 WAV、
  整场音频和时间线，排除符号链接与会话目录以外文件，不递归加入旧 zip。

`finish_summary()` 会先更新 JSON 包；音频最后关闭后应再次 `export()`，
以纳入最后播报的播放状态和整场录音清单。

## 数值结果播报

DASS-21 模式 `basic_summary()` 确定性播报各维度乘二后数值，并说明范围为 0–42。
某个维度有缺失时明确报告未答齐，不补零、不造出粗略分数。

依据：[官方计分模板](https://dass.psy.unsw.edu.au/Chinese/Chinese%20DASS21%20scoring%20template.pdf)、
[官方 FAQ 第 8、9、27、30 条](https://dass.psy.unsw.edu.au/DASSFAQ.htm)。
官方 FAQ 9 提醒计算机实施不能自动向受试者解释量表结果；第 5 条说明严重度标签不等于疾病诊断。
因此本次按需求提供可复核的数值反馈，默认不自动赋予“轻/中/重度疾病”结论；
如后续需要分级解释，应明确其用途与采用的专业审核方案，而不是由对话模型猜测。

## 网页 API 下载路径

- `GET /api/sessions/{id}/session_package.json`：下游结构化整场记录。
- `GET /api/sessions/{id}/session_package.zip`：包含文字、计分、音频与时间线的完整包。
- `GET /api/sessions/{id}/transcript.json`：完整对话事件，不限网页显示条数。
- `GET /api/sessions/{id}/full_audio/{file}.wav`：整场分轨 WAV，可范围读取播放。
- `GET /api/sessions/{id}/audio/{file}.wav`：按题或预聊分段音频。

整场 JSON 另含 `stage`、`wake_event` 和 `questionnaire_provenance`，下游可区分唤醒来源、
预聊或问卷阶段，以及题目译本和计分来源。`delivery=text` 表示仅界面文字输出，不代表语音播放。
完整包应在会话结束且录音写盘关闭后读取；运行中的提前 JSON 仅是当时的快照。

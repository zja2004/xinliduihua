# 人物检测、注视目标与待机语音唤醒

实现模块：`src/orin_voice/presence.py`，默认配置：`configs/robot.json`。

## 已实现的接口

`VisionPresence(config, on_wake, on_target, on_status=None)`：

- `config` 可为完整机器人配置或 `vision` 子对象。
- `start()` 启动摄像头后台线程；`stop()` 请求退出；`join(timeout)` 等待退出。
- `on_wake(event)` 在稳定人脸触发后调用，事件含 `trigger: vision`、单调时间戳、
  归一化 bounding box 与注视目标。
- `on_target(x, y, confidence)` 提供 [-1,1] 中心坐标，右、下为正。
  第三个参数为 1.0 表示有检测目标、0.0 表示丢失，**不代表校准概率**。
  丢失时只发一次 `(0,0,0)`。
- `on_status` / `status()` 提供打开中、观察中、错误、帧数、是否有人脸等状态。
- 输出经过低通、单次步长和死区限制，真正的舵机限位由硬件适配器负责。
- 本模块不直接写串口，也不调用未标定的舵机。

使用本机 OpenCV `CascadeClassifier.detectMultiScale` 和安装包附带的官方 Haar 正脸模型。
这是“稳定检测到正脸时唤醒”，不是全身人物检测、身份识别或活体检测。侧脸、遮挡、
逆光和距离过远可能漏检。输入仅允许本机设备索引或 `/dev/video*`，不访问远端摄像头。

默认需连续 6 帧观察到正脸；同一在场目标只唤醒一次。至少 3 秒没有检测到人脸后，
才重新允许触发，且两次视觉唤醒间隔至少 15 秒。机器人协调层还必须检查是否已有活跃会话，
不得在人机对话中不断创建新访谈。

`VoiceWakeListener(config, on_wake, recognizer=None, on_status=None)`：

- 仅在待机时开启麦克风，用项目现有 ASR 识别短语；支持传入共享的已加载识别器。
- 默认唤醒词：“你好小心”“小心小心”“你好机器人”。只匹配配置中的短语。
- 发言按能量门限和静默结束分段；本版不是专用 KWS 模型，唤醒响应取决于停顿与 ASR。
- 唤醒成功后先退出并关闭 `InputStream`，再调用 `on_wake`，方便协调层启动访谈录音。
- 协调层必须先 `stop()` / `join()` 待机监听，再开启另一条访谈流；不能同时开两套麦克风。
- 无麦克风、录音缓冲错误或三秒无采集回调时提供明确错误状态，不无限显示监听。
- 无唤醒词的环境对话只在内存中做识别，不在模块内保存为访谈数据。

硬件目标接入示例：

```python
vision = VisionPresence(config,
    on_wake=runtime.wake,
    on_target=lambda x, y, valid: hardware.track_target(x, y, visible=valid > 0))
```

## 环境配置与诊断

本地环境安装 `opencv-python-headless`（ARM64 wheel，版本 4.11.0.86）。保留已有 NumPy、
`sherpa-onnx` 和 `sounddevice`，不引入新的神经网络模型。

只读诊断：

```bash
cd /home/nvidia/Desktop/机器人头
.venv/bin/python scripts/check_robot_devices.py
```

诊断脚本列出 USB、摄像头、串口、PulseAudio 输入/输出、依赖与人脸模型位置，
不会打开串口或移动舵机。当前检查没有发现 `/dev/video*`、`/dev/ttyUSB*` 或 `/dev/ttyACM*`；
USB 列表仅有 Hub 和蓝牙，没有 USB 麦克风/摄像头。已有板载 ALSA 接口不证明存在可用实体麦克风。

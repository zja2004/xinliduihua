# 机器人头：运行与验收

工作目录：`/home/nvidia/Desktop/机器人头`。原“心理模型”不受本次改动影响。

## 当前实现与启动

```bash
cd /home/nvidia/Desktop/机器人头
bash scripts/robot.sh
```

会启动本机服务、打开 `http://127.0.0.1:18088`，并进入自动唤醒待机。
也可双击桌面“机器人头”启动项。仅打开网页、不启用待机使用 `bash scripts/launch-web.sh`。
网页可单独启用/停止待机或手动唤醒。

1. 待机时，人脸在镜头内稳定出现触发视觉唤醒；或对麦克风说“你好小心”“小心小心”“你好机器人”。
2. 语音待机先关闭麦克风再交给会话，避免同一设备双开。人物持续在场不会反复创建会话。
3. 唤醒后主动问候，可先与本地 4B 模型简短交谈；说“开始测评”进入 DASS-21。
4. 21 题由程序按原始题序控制。语音选分或按钮选分后主动推进，支持重听、跳过、返回修改和结束。
5. 播放期间持续收音；发音起始取消旧播放及嘴型。这里仍是能量检测/AEC原型，真实噪声环境的误打断与漏检需验收。
6. 结束后播报三个维度的数值（完整维度乘二，0–42）；缺题维度不填零、不计算；不输出疾病诊断或未经验证的严重程度判定。
7. 全部对话事件、逐题结果和整场音频自动导出，供后续处理。

视觉当前使用本地 OpenCV Haar **正脸**检测，不等同于任意姿态全身人物识别，也不做身份或活体识别。
无人、侧脸、遮挡或光线不足均可能影响视觉唤醒。配置见 `configs/robot.json`。

## 硬件真实状态与眼球/嘴型

压缩包在 `机器人头操作代码/解压/`，原始上传保留。
ROS2 Humble 的四个依赖包及 gimbal C++ 库已构建；OpenCV 4.11 与 pyserial 3.5 已装入新项目环境。
详细接口见 [机器人头硬件接入](机器人头硬件接入.md)。

**本次检查没有 `/dev/video*`、`/dev/ttyACM*`、`/dev/ttyUSB*`，USB 仅 Hub 与蓝牙，音频仅板载设备。**
因此不能宣称当前实际眼球跟随、嘴型、摄像头和耳机同时录放已经联调成功。
`configs/head_hardware.json` 默认 `backend: dry_run`，网页明确显示“模拟（未运动）”。

真实运动需要：

- 确认人头实际连接方式和 V2.5 控制板；不猜测板载 `ttyTHS` 的用途。
- 接通本机唯一 ROS `device_io` 驱动，取得当前有效的 `/device/status` 与 24 轴 `/device/calibration`。
- 使用与驱动一致的本机 ROS 域（默认 93），确认实时零点、最小/最大角度。
- 硬件配置改为 `backend: ros`、`calibration_confirmed: true`。桥接器仍须检测设备连接和有效标定，超时停止动作。

程序不沿用包中远程设备 IP，不启动未校准的头部、脖子或 Yaw 运动。
眼球目标使用归一化人脸中心，经平滑、限步和实时角度边界后发布；嘴型使用说话文本与实际输出 PCM。

检查当前设备：

```bash
.venv/bin/python scripts/check_robot_devices.py
```

## 输出给下游的文件

每场在 `sessions/会话编号/`：

- `answers.json`：21 题、原始转写、选分、状态、三维计分。
- `events.jsonl`：持久化事件，含唤醒前因、用户与机器人话语；机器人有 planned/playing/completed/interrupted/failed 标记。
- `transcript.json`：合并后的完整对话事件。
- `audio/`：逐题回答、预聊回答、未识别音频。
- `full_audio/`：整场麦克风与机器人实际提交音频分轨、时间线、完整性 manifest。
- `summary.txt`：完成后的数值结果和一般反馈。
- `session_package.json`：统一下游 schema（`robot-head-session/1.0`），含21题、计分、来源、唤醒方式、对话和媒体索引。
- `session_package.zip`：包含以上文本记录和音频文件。

用户与机器人整场音频为分轨紧凑保存，使用时间线还原间隔和重叠；不是已经混成的声学现场录音。
只记录实际提交给设备的机器人音频，不把被取消的未播放合成结果记成完整播报。
队列丢块、写入失败或没有任何输入帧时不会标记录音完整。摄像头本次用于唤醒与注视，尚未录制视频。

## 新增 API

- `GET /api/robot/status`：视觉/语音待机、模型、硬件、设备信息。
- `POST /api/robot/actions`，`{"action":"arm"}` / `disarm` / `wake`。
- 手动唤醒测试：`{"action":"wake","mode":"text"}`，不打开麦克风；真实语音使用 voice。
- `POST /api/sessions` 仍支持原直接测评模式；可加 `"robot": true` 从交谈阶段开始。
- `GET /api/sessions/{id}/session_package.json` / `session_package.zip`。
- `GET /api/sessions/{id}/transcript.json`。
- `GET /api/sessions/{id}/full_audio/{file}.wav`，支持 HTTP Range 以回放较长音频。

本机 API 与原问卷入口兼容，同一时间只允许一场访谈。

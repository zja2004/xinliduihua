### speak_mouth

它是 ROS 2 嘴型规划器，不是串口或音频播放器。原接口是：

- 输入 `/dialogue/utterance`（`robot_interfaces/DialogueUtterance`）、`/dialogue/tts_stream`（`AudioFrame`）。
- 输入 `/device/status` 和 `/device/calibration`，配对设备连接与实时标定。
- 输出 `/mouth/target`（`MouthTarget`）：S11、S12、S13、S14、S15、S16、S17、S22 八轴相对实时 Zero 的度数偏移。
- 输出 `/audio/playback`，原系统由独立 audio_io 播放。
- 嘴型规则为拼音 + 实时 PCM 能量，100 Hz Ruckig 平滑；这是近似在线对齐，不是强制声学对齐。

### 眼球追踪参考包

它是 V22 项目部分源码快照。`face_tracking.py` 提供归一化人脸坐标及 S7/S10 眼球映射。
完整路径是视觉目标 → FaceEyeController → 动作合成 → 唯一串口写者 → V2.5 头板。
包中 `v22_serial_session.py` 引用了未打包的 `cmd8_identity.py`、`headboard_telemetry.py`，完整头部运行时不能仅凭此 zip 直接启动。
`HeadTool V2.5` 发送完整 S1–S24 帧（规划字节 + 24 个小端百分之一度 uint16），不能用自拟的“眼球 JSON 串口命令”替代。
本次没有启用参考包的脖子/Yaw 候选运动路径。

## 新项目适配器

`src/orin_voice/head_hardware.py` 对外接口：

```python
head.start()
head.track_target(x_norm, y_norm, visible=True)  # [-1,1]，右/下为正
head.begin_utterance(uid, text)
head.audio_chunk(uid, samples, rate)             # 实际送往扬声器的 float PCM，建议每 20ms
head.cancel_utterance(uid)                        # 打断立即取消旧嘴型
head.end_utterance(uid)
head.status()
head.close()
```

配置：`configs/head_hardware.json`。默认 `backend: dry_run`，仅记录目标、轮次和音频块数量，不打开串口、不移动舵机。

`backend: ros` 时由 `scripts/head_ros_bridge.sh` 启动使用系统 Python/ROS overlay 的独立 helper，避免项目 venv 与 ROS Python 混用。
helper 直接复用上传的 `MouthMotion`、`VisemePlanner`、Ruckig，按正在播放 PCM 生成嘴型；不再次发布 `/audio/playback`，避免同一声音被播放两遍。
眼球通过 `/eye/target` 发布，`EyeTarget.offsets_deg` 顺序为 S7、S8、S9、S10；本版本只动 S7/S10，眼皮保持实时 Zero。
每步限幅、低通平滑、目标超时回中，并与设备实时 Min/Max 取交集。

真实运动要求：配置显式 `calibration_confirmed: true`，且 ROS 设备状态 `connected=true, calibration_ready=true`，同时取得完整有效的 24 轴标定。否则不发布运动目标。
`device_io` 必须是唯一的头板串口写者；不要同时启动上传原节点、旧 V22 runtime 和新桥接节点向同一执行器发布冲突命令。
本实现不会自动启动扫描/校准或对串口写位置。实际校准和接入需在设备被识别后执行。

## 当前连接检查的实测限制

本次检查 `/dev/video*`、`/dev/ttyACM*`、`/dev/ttyUSB*` 和 `/dev/serial/by-id` 均未发现。
USB 仅列出集线器和 Realtek 蓝牙；没有摄像头、ME01TC 耳机或头板 USB 串口。
有线网口 `enP8p1s0` 为 DOWN；邻居表仅有 Wi-Fi 路由器，没有发现已连接人头网口。
没有运行中的 device_io / speak_mouth / head_motion 进程或相关用户服务。
存在的 `ttyTHS1/2`、`ttyTCU0` 是板载接口，不能因此认定它们就是头板，未尝试打开或发命令。

所以现在已配置并验证的是软件环境、消息接口、受控动作适配与离线测试，不是眼球/嘴部机械联调成功。
接入后需要核对供电、数据线、设备路径、实时标定、方向、运动范围和声画时序；无须让用户猜一个控制板协议。

# Orin 全语音心理对话：ASR + LLM + TTS，还是端到端语音模型？

调研日期：2026-10-22（Asia/Shanghai）。补充需求：学生的输入、系统的输出均为语音。

实施更新：用户已确认设备为 Orin NX 8GB，并选择 Qwen3.5-4B-Q4_K_M 基线与社区 Qwen3.8-4B-Distill-Q4_K_M 实验组，共用 sherpa-onnx ASR 和 Kokoro TTS。项目入口与实际验证边界见本目录 README.md；本报告中的候选建议不代表已经完成部署。

## 1. 结论

**第一版建议使用 ASR → 文本 LLM → TTS，并保留一条轻量的原始音频分析支路；端到端语音模型作为对照实验，不作为唯一的筛查与安全链路。**

这是针对“心理筛查、情绪识别、心理科普、危机线索提示、档案管理”做出的工程判断，不是说级联模型在所有任务上都优于原生语音模型。全语音是产品交互形式，内部有文本不妨碍学生全程说话、听回复。Hugging Face 的 speech-to-speech 项目提供了可参考的模块化语音助手实现。[V01]

原生语音模型值得研究，因为它们可直接处理音频并生成语音，一些模型还支持边听边说。但必须区分：音频输入不等于音频输出；流式输出不等于全双工；模型支持流式不等于所用推理接口返回实时音频块；有文本输出也不等于一定能在播出前完成安全审查。

**验证边界：本次只核验官方资料，没有接入 Orin，没有做中文学生案例测试，没有测量实际延迟和内存。配置是候选，不是已经跑通的承诺。**

## 2. 两种路线的取舍

以下为基于架构的工程判断，最终应由同设备、同音频、同安全流程的测试决定。

| 维度 | ASR + 文本模型 + TTS | 原生/端到端语音模型 |
| --- | --- | --- |
| 全语音体验 | 可以实现，学生不用看中间文本 | 可以实现，部分支持原生全双工 |
| 声音信息 | 只有转写会丢失一些声学信息；可增加原始音频支路 | 具有直接利用声音特征的接口，但实际可靠性要验证 |
| 筛查和档案 | 可明确保存确认后的题目、选项、摘要来源和已播放内容 | 可接结构化工具，但仍需独立校验与来源记录 |
| 输出安全控制 | 可以先检查待播文本，再交给 TTS | 要检查是否能拦截尚未播放的内容；直接播出后无法撤回 |
| 故障定位 | 可区分没听清、推理错误和合成错误 | 需要在音频理解、生成和工具接口之间定位问题 |
| 延迟 | 多阶段有额外开销；流式、分句和合理调度可降低等待 | 原生全双工具有交互潜力，但不能据参数量断言在 Orin 更快 |
| 领域适配 | 可以先只适配文本模型的语言风格、工具和边界 | 需要核验可微调组件、语音数据和部署后端，不能假设改文本模块就足够 |

心理场景的选择依据是“安全可审查、流程可测试、档案可追溯”，而不只是声音是否像真人。WHO 提醒健康领域生成式模型可能产生错误、偏差和自动化依赖，要求适用场景验证与治理。[V16]

## 3. 推荐的语音系统结构

```text
麦克风
  │
  ├── 回声消除 / 降噪 / VAD / 发言结束检测
  │           │
  │           └── ASR → 暂定/最终转写 → 关键内容回读确认
  │                                       │
  └── 经同意的原始音频短缓冲 → 声学/情绪辅助线索 ─┤
                                          ▼
                           受控会话流程 + 独立安全检查
                                          │
                   ┌──────────────────────┼───────────────────┐
                   ▼                      ▼                   ▼
              Qwen 支持性对话       审核知识库 RAG       正式量表/固定计分
                   └──────────────────────┼───────────────────┘
                                          ▼
                          待播短句 → 输出检查 → TTS
                                          ▼
                               可中断播放 → 扬声器

独立支撑：人工支持通道、通知回执、权限档案、最小必要审计。
```

这里的“情绪线索”不能替代学生自述或专业评估。低置信或互相矛盾的信息，应允许未知并澄清，不把悲伤、低声或长停顿直接写成心理疾病标签。原始录音默认不长期保存，保存用途、授权和期限需单独确定。

建议第一版实现“轮流交谈 + 可随时打断”，不强求一开始原生全双工。VAD 只判断是否有语音，发言结束还应考虑停顿和话语是否完整，不能把学生犹豫自动当成说完。

## 4. 级联方案的具体候选

| 环节 | 候选 | 已核实信息与选择边界 |
| --- | --- | --- |
| 新一些的 ASR | Qwen3-ASR-0.6B | 2026-01-29 发布，支持中文及多种方言、离线/流式；官方仓库目前说明流式接口使用 vLLM，需要单独验证 Jetson 后端与整机内存 |
| 轻量流式 ASR | sherpa-onnx 中文 streaming Zipformer | 官方列有中文 INT8 流式模型和麦克风实时识别示例；可作为 8GB 设备的 CPU/ONNX 候选，模型版本和权重许可分别核对 |
| 对话模型 | Qwen3.5-4B 或 Qwen3-4B-Instruct-2507；资源充足再比较 Qwen3-8B | 使用前一份报告中的文本底座方案；选好受支持后端及量化版本，不把视觉模块默认加载进纯语音系统 |
| 新一些的 TTS | Qwen3-TTS-12Hz-0.6B-CustomVoice | 2026-01-22 发布，Apache-2.0，支持中文及预置音色；0.6B 版本不能直接沿用 1.7B 所有指令式风格控制能力 |
| 低资源 TTS | sherpa-onnx 的 Kokoro 中文版本 | 官方提供中英模型和 INT8 包；适合先测试 CPU 路线，最终选择听感、读字准确性与资源的平衡 |
| 音频辅助线索 | SenseVoiceSmall 等音频分析模型 | 官方支持情绪/声音事件识别；不是经过本项目验证的心理筛查工具，可先离线实验而非强行全部常驻 |

来源：[V02][V03][V04][V05][V06][V07]。文本模型的来源见前一份选型报告。

注意部署细节：Qwen3-ASR 的模型能力与当前官方流式实现的依赖是两回事。若 vLLM 在目标 JetPack 上过重或不适配，可以测试轻量流式 ASR，或先做 VAD 分段识别；后者不要宣传成已经实现真正的增量识别。

TTS 同样需要分清“支持流式的模型”和“你调用的 API 是否边生成边返回音频”。第一轮可用经审查的短句分段合成；真正的低延迟音频块输出要另外测。llama.cpp 当前官方 TTS 文档已列 Qwen3-TTS 的路径，但这不证明所有尺寸、变体和 Jetson 配置都已可用，更不能把 1.7B Base 示例当成 0.6B CustomVoice 的验证结果。[V15]

## 5. 原生语音模型：哪些值得试

| 模型 | 核实结果 | 对本项目的判断 |
| --- | --- | --- |
| MiniCPM-o 4.5 | 2026 年的 9B 全模态模型；支持中英文实时语音、全双工；官方提供量化与本地部署路径 | 最值得进入原生语音对照的候选之一，但不是 8B，也不是 8GB 设备的默认方案 |
| MiniCPM-o 2.6 | 2025 年模型；总参数约 8B，由语言、音频理解、语音生成和视觉组件组成 | 若严格限制 8B，可以作旧版本对照，但不能把它称作当前最新 |
| Qwen2.5-Omni-7B | Apache-2.0；Thinker-Talker 架构，支持音频输入及文本/语音输出 | 可做原生语音研究对照；不能用纯文本 7B 的内存直接估算完整语音链路 |
| Qwen2.5-Omni-3B | 更小；模型卡标记 qwen-research | 不能因为参数小就默认适合正式部署；必须先审查研究许可 |
| NVIDIA PersonaPlex-7B-v1 | 2026-01-15 发布；7B 全双工模型；模型卡定位英语语音输入和英语输出 | 不列为中文学生场景主选；NVIDIA 发布不等于已在 Orin 上验证 |
| Qwen3-Omni-30B-A3B-Instruct | 原生多模态、可语音输出；30B-A3B 是 MoE 规模标识 | 不属于 3B 总权重级模型，不能按“激活 3B”套用小模型内存预算 |

来源：[V08][V09][V10][V11][V12][V13]。

MiniCPM-o 4.5 官方本地部署表给出原版约 19GB、GGUF 约 10GB、AWQ 约 11GB 的参考值。这些是作者场景下的参考，不是用户 Orin 上的实测，也不保证某种量化路径完整支持目标实时语音功能。不能把它承诺为 8GB 设备可完整实时运行。[V08]

Qwen2.5-Omni 模型卡中的内存表包含视频输入条件；本项目只用语音，不能机械引用视频的数字作为语音最低内存，也不能忽略 Talker、音频编码解码和缓冲。必须测完整加载及多轮运行。

如果选择原生模型，仍建议保留可审计的文本/结构化旁路、安全检查、确定性量表计分和人工支持流程。原生模型不自动替代业务系统。

## 6. 按内存做候选配置

以下是建议测试的起点，不是已跑通配置。

### 8GB Orin

- 文本 LLM 先用 4B 级量化模型，而不是先塞入 8B。
- ASR 优先比较 sherpa-onnx 中文流式模型与 Qwen3-ASR-0.6B 分段识别。
- TTS 先验证 Kokoro 中文 CPU 路线；有余量再试 Qwen3-TTS-0.6B。
- 不把额外 4B 安全分类器、情绪模型、重型 ASR/TTS 全部常驻。
- 留意机器人控制、摄像头、桌面和系统内存；模型算力不应侵占有实时要求的设备控制任务。

### 16GB Orin

- 优先测试 Qwen3-ASR-0.6B + Qwen 4B + Qwen3-TTS-0.6B。
- 再单独把对话模型替换为 Qwen3-8B，比较完整会话延迟、内存与任务收益。
- MiniCPM-o 4.5 量化版可以加入对照，但先核验后端的语音路径，不只测试文本生成。

### 32/64GB Orin

- 级联和原生语音两条路线都有更大实验空间。
- 依然不能用“能装下”代替“能持续实时说话、打断、接着听”。

## 7. 全语音的关键验收点

1. **关键语义不丢失**：单独统计否定词、时间、主体、计划/已经发生等安全相关语义错误；普通 CER/WER 不足以证明安全。对量表选项和关键陈述适时回读确认，不允许 LLM 补写没听清的内容。
2. **保持正式量表效度边界**：题目与选项应使用审核版本，不让对话模型自由改写；语音施测是否适用、听力/理解困难如何处理，应由专业团队确认，不能假定与原来的自填形式完全等价。
3. **播出前控制**：先检查待播短句，再进入 TTS；高敏感流程可使用审核过的固定语音。检查不能保证绝对安全，仍需真实的人类接管链路。
4. **可打断并正确记忆**：学生开口后及时停播、取消尚未播放的 TTS 队列；会话记录区分“已生成”“已合成”“实际播出”，避免后续推理认为学生听到了没播出的建议。
5. **回声与误触发**：测试扬声器的回答被麦克风再次识别、多人说话、门外声音和静音；未经确认的背景语音不能写入某个学生的正式档案。
6. **真实首音延迟**：从学生实际说完到系统第一段有效语音，不只报 LLM tokens/s。分别记录结束检测、ASR 最终结果、检索/检查、LLM 首句和 TTS 首音时间。
7. **持续播放能力**：测 TTS 实时率、长回复断音、打断后恢复、长会话内存增长；对比 CPU/GPU 调度，而不预设全部放 GPU 更快。
8. **错误与离线降级**：未识别清楚就澄清；模型异常时保留审核过的说明和人工求助入口；通知未送达不能报告已送达。
9. **隐私与声音使用**：明确告知这是 AI；不默认保存录音，不默认用录音训练；先用授权预置音色，不克隆真实老师、家长或学生的声音。

建议测试音频包含普通话、校园日常表达、口音、低声、哭泣、长停顿、被打断、否定/转述/历史经历；涉及心理安全的案例与评分标准由专业人员审核。不得直接以语音情绪识别的准确率代替危机线索检测的验证。[V16]

## 8. 微调和 Agent 的定位

先把听清、可控回复、读对、能打断、人工支持和档案权限跑通，再考虑微调。级联方案可先只微调文本模型的支持性表达、工具参数与边界；ASR 出错不应靠修改对话模型来掩盖。

第一版用受控会话状态机即可，不需要多个自主 Agent。原生语音与 Agent 也是两个不同维度：换成语音模型，不会自动获得可靠的量表、通知或档案能力。

下一步需要的信息：**Orin 的完整型号与内存、JetPack 版本、麦克风/扬声器或麦阵列型号、是否还同时运行机器人程序。**
